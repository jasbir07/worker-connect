1️⃣ Centralized Error Handling (VERY IMPORTANT)
❌ Problem

Right now, errors are handled differently in every controller.

✅ Solution

Use one global error handler.

Create: backend/src/middlewares/errorMiddleware.js
exports.errorHandler = (err, req, res, next) => {
  const statusCode = res.statusCode === 200 ? 500 : res.statusCode;

  res.status(statusCode).json({
    message: err.message || "Server Error",
    stack: process.env.NODE_ENV === "production" ? null : err.stack
  });
};

Use it in app.js (LAST middleware)
const { errorHandler } = require("./middlewares/errorMiddleware");

app.use(errorHandler);


📌 Interview line

“We use centralized error handling to keep controllers clean and maintain consistent API responses.”

2️⃣ Async Error Wrapper (Cleaner Controllers)
Create: backend/src/utils/asyncHandler.js
const asyncHandler = (fn) => (req, res, next) =>
  Promise.resolve(fn(req, res, next)).catch(next);

module.exports = asyncHandler;

Example usage:
const asyncHandler = require("../utils/asyncHandler");

exports.getAllJobs = asyncHandler(async (req, res) => {
  const jobs = await Job.find({ status: "open" });
  res.json(jobs);
});


✔ Less try/catch
✔ Cleaner code

3️⃣ Pagination (BIG PERFORMANCE BOOST)
❌ Problem

If there are 10,000 jobs → API slow

✅ Solution

Paginate results.

Update getAllJobs
exports.getAllJobs = asyncHandler(async (req, res) => {
  const page = Number(req.query.page) || 1;
  const limit = 5;
  const skip = (page - 1) * limit;

  const jobs = await Job.find({ status: "open" })
    .skip(skip)
    .limit(limit)
    .sort({ createdAt: -1 });

  res.json(jobs);
});

Test:
GET /api/jobs?page=1
GET /api/jobs?page=2


📌 Interview line

“We use pagination to limit dataset size and improve response time under heavy load.”

4️⃣ Input Validation (Security)
Install:
npm install express-validator

Example: Job creation validation
const { body } = require("express-validator");

exports.createJobValidation = [
  body("title").notEmpty(),
  body("description").notEmpty(),
  body("location").notEmpty()
];


Use in route:

router.post(
  "/",
  protect,
  authorize("client"),
  createJobValidation,
  createJob
);


📌 Prevents:

Empty input

Bad data

Basic attacks

5️⃣ Rate Limiting (Protect APIs)
Install:
npm install express-rate-limit

Create limiter:
const rateLimit = require("express-rate-limit");

const apiLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 100
});

app.use("/api", apiLimiter);


📌 Interview line

“Rate limiting protects APIs from abuse and brute-force attacks.”

6️⃣ Security Headers (Optional but Good)
